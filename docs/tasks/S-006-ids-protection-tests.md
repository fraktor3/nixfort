## Повтор после остановки 26.10 (агент 1.3.1) — выполнять ВМЕСТО частей A и B
Причина остановки: после установки пакета служба Suricata падала на `eth0` (такого интерфейса на шлюзе нет), и systemd заблокировал её запуск: «Start request repeated too quickly». Агент 1.3.0 не смог запустить датчик, сам откатил профиль, но ответил ERROR, поэтому контроллер показал «состояние неизвестно». В агенте 1.3.1 блокировка сбрасывается перед запуском, а подтверждённый откат возвращается как «не применено» (ADR-044).
R1. nx-controller: `git pull && make up` → `make selfcheck` → `make itest` (0 failed; тест netns в контейнере теперь пропускается).
R2. Агент 1.3.1 на трёх узлах (как в части A, шаг 2).
R3. Только чтение на шлюзе — проверить, что откат 26.10 был полным: `ls /etc/suricata/nixfort-sensor.yaml` (нет такого файла), `grep -c nixfort-sensor /etc/suricata/suricata.yaml` (0), `systemctl list-timers --all | grep nixfort` (пусто), `sudo grep -l '"kind": "suricata"' /var/lib/nixfort/snapshots/*/meta.json | xargs sudo grep -h rolled_back` (`"rolled_back": true`). Если хоть что-то не так — остановиться.
R4. Снимок `lab-s006-before` не трогать. Руководитель: «Аудит» → «Запустить аудит» (IDS-01 FAIL — служба не работает, IDS-02/03 FAIL) → «Сформировать план». Ожидается **один** шаг: «Датчик Suricata на интерфейсе enp0s9…» (Suricata уже установлена). Старый план в состоянии UNKNOWN не трогать.
R5. «Утвердить и выполнить» → дальше с шага 7 карточки (ожидается «Применён и подтверждён») и части C, D.

## Часть A — обновление (Cursor)

2. Агент на трёх узлах, как в S-004 (часть A, шаг 2) → `agent_version":"1.3.0"`.
3. Только чтение: на nx-gateway `ip -br addr` — у `enp0s9` адрес 10.88.0.1 (сеть пользователей); `free -m`; `sudo apt-get update -q | tail -2` (нужен для установки Suricata). На nx-client `ls -l /usr/bin/ssh`. В интерфейсе у узла nx-gateway роль «Датчик IDS» и интерфейс `enp0s9` — если не так, сказать руководителю (исправляет он через «Изменить узел»).

## Часть B — датчик через план (руководитель нажимает)

6. «Сформировать план исправлений» (флажок ключа не ставить). Ожидается 2 шага на nx-gateway: «Установить Suricata…» (необратимо) и «Датчик Suricata на интерфейсе enp0s9…» (MEDIUM, IDS-01…03). Скриншот.
7. «Утвердить и выполнить». Установка занимает до нескольких минут. Ожидается план «Применён и подтверждён», постпроверка «Suricata 7.0.3 работает на enp0s9, EVE пишется, правила NIXFORT загружены»; «До / после»: IDS-01…03 → PASS. Скриншоты.
8. Cursor (только чтение) на шлюзе: `systemctl is-active suricata`, `sudo cat /etc/suricata/nixfort-sensor.yaml`, `grep -n nixfort-sensor /etc/suricata/suricata.yaml`, `sudo suricata --dump-config | grep -E '^af-packet.0.interface|^rule-files'`, `free -m` (сколько осталось памяти), `systemctl list-timers --all | grep nixfort` (пусто).

## Часть C — проверка защиты (руководитель нажимает на странице «Проверка защиты»)
10. «Тестовое событие IDS» → «Запустить». Ожидается «Защита сработала»: Suricata — событие sid 9000001 от 10.88.0.10 → 10.99.0.10:80. Скриншот. На странице «IDS» событие видно.
11. «Сканирование портов» → «Запустить». Ожидается «Защита сработала»: межсетевой экран — открыт только 80; Suricata — событие sid 9000002. Скриншот.
12. «Подбор пароля SSH» → «Запустить» (~1 мин). Ожидается «Защита сработала» по трём уровням: межсетевой экран (через шлюз до sshd дошло 0 из 6), Suricata (sid 9000003), Fail2ban (10.77.0.40 в списке блокировки). Скриншот.
13. Cursor: на сервере `sudo fail2ban-client status sshd` — `10.77.0.40` в Banned IP list; на шлюзе `sudo grep -c '"signature_id":900000' /var/log/suricata/eve.json` > 0. Затем снять бан, не дожидаясь 10 минут: `sudo fail2ban-client set sshd unbanip 10.77.0.40`.

## Часть D — «журнал недоступен» ≠ «событий нет» (AT-15, Cursor меняет только шлюз, руководитель нажимает)
14. На шлюзе: `sudo systemctl stop suricata && sudo mv /var/log/suricata/eve.json /var/log/suricata/eve.json.s006`. Руководитель: «Тестовое событие IDS» → ожидается «Проверка не выполнена», Suricata — «журнал EVE недоступен для чтения» (нет данных).
15. На шлюзе: `sudo mv /var/log/suricata/eve.json.s006 /var/log/suricata/eve.json` (служба всё ещё остановлена). Руководитель: «Тестовое событие IDS» → ожидается «Защита не сработала», Suricata — «событий нет».
16. На шлюзе: `sudo systemctl start suricata`, подождать 20 с. «Тестовое событие IDS» → снова «Защита сработала». Скриншоты 14–16.
