# S-005 — Межсетевой экран на шлюзе с проверкой соединений до/после (Cursor + руководитель)

| Поле | Значение |
|---|---|
| Зависит от | S-004 принята; коммит «T-013: nftables» запушен |
| Код | не менять; ошибки — полный вывод в отчёт |
| Читать | `docs/NODE_AGENT_PROTOCOL.md` §7, `docs/ARCHITECTURE.md` §6, `docs/DECISIONS.md` ADR-034…038, `docs/TESTING.md` AT-12…14 |
| Проверяет | AT-12 (политика применена и доказана пробами), AT-13 (ошибочное изменение откатывается узлом), FW-01…04 |

Что нового: шаг плана «Межсетевой экран» на nx-gateway (nftables, таблица `inet nixfort`), TCP-пробы с nx-client до и после изменения, страница «Сетевые тесты», поле проекта «Дополнительные адреса администраторов».

**Важно про доступ.** После применения политики SSH к шлюзу разрешён только с адреса контроллера (10.77.0.10) и с адресов из поля проекта. Доступ с Windows через проброс портов VirtualBox приходит с адреса **10.0.2.2** — его нужно добавить в шаге 6, иначе `ssh nx-gateway` с Windows перестанет работать (с nx-controller — продолжит).

## Часть A — обновление (Cursor)
1. nx-controller: `cd ~/nixfort && git pull && make up` → `make selfcheck` (без [FAIL]) → `make itest` (ожидается **0 failed**, не меньше 380 passed; тест ядра nftables в контейнере пропускается — он требует root).
2. Обновить агента на трёх узлах тем же способом, что в S-004 (часть A, шаг 2). В выводе — `agent_version":"1.2.0"`.
3. Проверить шлюз (только чтение): `ssh labadmin@10.77.0.20 'sysctl net.ipv4.ip_forward; sudo nft list ruleset | head -20; systemctl is-enabled nftables; ufw status 2>/dev/null | head -1'` → `ip_forward = 1`, правил NIXFORT нет, UFW неактивен.
4. Проверить, что на сервере слушают 80 и 8080: `ssh labadmin@10.77.0.30 'ss -ltn | grep -E ":(80|8080) "'`. Если чего-то нет — записать в отчёт и сказать руководителю (без этого блокировка не будет доказуема).
5. Снимок всех четырёх ВМ **`lab-s005-before`** («после S-004, агенты 1.2.0, межсетевого экрана нет»).

## Часть B — настройка проекта и политики (руководитель в интерфейсе, Cursor подсказывает)
6. Проект → «Изменить» → «Дополнительные адреса администраторов»: `10.0.2.2` → сохранить. На странице проекта появится «администраторы 10.0.2.2».
7. «Политика соединений»: сверить активную версию. Нужны три потока, все с «Проверять с узла» = nx-client:
   | Назначение | Источник | Назначение | Действие | Критичный |
   |---|---|---|---|---|
   | Веб-сервер | 10.88.0.0/24 | nx-server 10.99.0.10:80 | Разрешить | да |
   | Служебный порт | 10.88.0.0/24 | nx-server 10.99.0.10:8080 | Запретить | — |
   | SSH сервера из сети пользователей | 10.88.0.0/24 | nx-server 10.99.0.10:22 | Запретить | — |
   Если активная версия отличается — «Изменить (создать черновик)», исправить, «Активировать». Скриншот политики.
8. «Сетевые тесты» → «Проверить соединения». Ожидается: 80 OPEN «Соответствует»; 8080 и 22 OPEN «Нарушение» (запрещённые соединения пока открыты — это исходное состояние). Скриншот.

## Часть C — исправление через план (руководитель нажимает)
9. «Аудит» → «Запустить аудит». Ожидается на nx-gateway: FW-01 PASS, FW-02 FAIL, FW-03 FAIL, FW-04 «Не применимо».
10. «Сформировать план исправлений» (флажок ключа не ставить). Ожидается шаг **nx-gateway — «Межсетевой экран по политике vN…»**, риск HIGH, исправляет FW-02, FW-03. Описание содержит «SSH к шлюзу — только с 10.77.0.10, 10.0.2.2» и «Проверка пробами до/после (3 из 3 потоков)». Скриншот.
11. Подтверждение → «Утвердить и выполнить». В журнале задания: «пробы соединений до изменения» → применение → «постпроверка — OK: правила vN в ядре, пробы: 3 из 3 соответствуют». План «Применён и подтверждён».
12. На странице плана таблица **«Пробы соединений»**: до — 80/8080/22 OPEN; после — 80 OPEN «Соответствует», 8080 и 22 TIMEOUT «Соответствует — блокировка доказана». Ниже «До / после»: FW-02, FW-03 → PASS, FW-04 → PASS. Скриншоты.
13. Cursor (только чтение): `sudo nft list table inet nixfort`, `sudo cat /etc/nftables.d/nixfort.nft | head -5`, `grep nftables.d /etc/nftables.conf`, `systemctl is-enabled nftables` (enabled), `systemctl list-timers --all | grep nixfort` (пусто). С Windows: `ssh nx-gateway hostname` — работает. С nx-client: `nc -zv -w3 10.99.0.10 80` — succeeded, `nc -zv -w3 10.99.0.10 8080` — timeout.
14. «Сетевые тесты» → «Проверить соединения»: все три «Соответствует». Скриншот.

## Часть D — ошибочное изменение, отрезающее управление (AT-13, Cursor, ручной вызов агента)
Имитируем ошибку администратора: правила, где SSH к шлюзу разрешён с чужого адреса. Без commit узел должен сам вернуть прежние правила.
15. На nx-controller (ключ — во временной копии, удалить после):
    ```
    sudo cp secrets/controller_ed25519 /tmp/ck && sudo chown $USER /tmp/ck
    python3 agent/tools/make_request.py nft.apply_policy.v1 '{"policy_version":99,"management_sources":["10.77.0.99"],"forward_allow":[{"src":"10.88.0.0/24","dst":"10.99.0.10","port":80}],"input_allow":[],"rollback_timeout_s":30}' | ssh -i /tmp/ck nixfort@10.77.0.20
    ```
    Ответ приходит (уже открытое соединение не рвётся). Записать `snapshot_id` и время. **commit не вызывать.**
16. Сразу: `ssh -o ConnectTimeout=5 labadmin@10.77.0.20 true; echo $?` → ошибка (управление потеряно). Повторять каждые 10 с; записать момент, когда снова `0`. Ожидается ≤ 60 с от шага 15.
17. После восстановления: `sudo nft list table inet nixfort | head -3` → снова `policy_version=<N из части C>`; в `/var/log/nixfort-agent.log` — `timer rollback snapshot=<id> result={'rolled_back': True ...}`; `mutation.snapshot_status.v1` → `rolled_back: true`. «Сетевые тесты» → все «Соответствует». `rm /tmp/ck`.

## Часть E — правила переживают перезагрузку (Cursor)
18. `ssh labadmin@10.77.0.20 'sudo reboot'`, подождать ~1 мин. `sudo nft list table inet nixfort | head -3` → таблица на месте. В интерфейсе «Инвентаризация» nx-gateway → OK. «Сетевые тесты» → все «Соответствует».
