# Как мы работаем

> **С 22.10.2026 (ADR-018):** код пишет архитектор (Claude) и кладёт в эту папку; Cursor выполняет карточки `docs/tasks/S-xxx` — развёртывание и проверка на стенде. Таблица ролей ниже описывает исходную схему; действующие роли — в `docs/STATUS.md`. Стартовая фраза для Cursor та же, только с номером S-карточки.

## Роли
| Кто | Делает | Не делает |
|---|---|---|
| Руководитель (ты) | запускает задачи в Cursor, подтверждает планы, гоняет стенд, `git commit/push`, передаёт архитектору «проверь T-xxx» | не принимает код без ревью архитектора |
| Архитектор (Claude, проект «Диплом») | пишет карточки задач, отвечает на архитектурные вопросы, ревьюит код в папке, принимает/возвращает, ведёт `DECISIONS.md`, пишет текст ВКР | не пишет основной код (кроме критичных исправлений) |
| Исполнитель (Cursor) | реализует карточку, пишет и запускает тесты, обновляет `STATUS.md` | не меняет архитектуру и объём |

## Цикл одной задачи
1. Открой Cursor в папке `nixfort`. **Новый чат** (Agent, модель — твоя).
2. Вставь стартовую фразу (ниже), подставив номер задачи.
3. Cursor присылает план → проверь, что он совпадает с карточкой → «Подтверждаю, выполняй».
4. Cursor пишет код, тесты, запускает тесты, присылает отчёт.
5. Ты: `git add -A && git commit -m "T-00X: <кратко>" && git push`.
6. Пишешь архитектору: «проверь T-00X». Архитектор читает код в папке и отвечает: **принято** или **список исправлений**.
7. Исправления → в **тот же** чат Cursor. Принято → архитектор обновляет STATUS, следующая задача — новый чат.

## Стартовая фраза для нового чата Cursor
```
Ты исполнитель проекта NIXFORT. Прочитай AGENTS.md, docs/PROJECT_CONTEXT.md, docs/STATUS.md
и карточку docs/tasks/T-00X-*.md, а также документы, на которые она ссылается.
Сверь STATUS.md с git log. Затем: перескажи задачу в 3–5 строках, перечисли файлы,
которые создашь/изменишь, и тесты. Код не пиши до моего подтверждения.
```

## Если чат Cursor «поплыл»
Признаки: повторяет ошибки, забывает правила, переписывает лишнее. Действия:
1. Не спорь. `git status` / `git diff` — посмотри, что он наделал.
2. Плохие изменения: `git checkout -- .` (откат незакоммиченного) или `git reset --hard HEAD`.
3. Новый чат + стартовая фраза + «Предыдущая попытка не удалась: <в чём>. Учти это».

## Если ты ушёл в новый чат с архитектором (Claude)
Достаточно сказать: «Продолжаем NIXFORT, папка подключена». Архитектор читает `docs/STATUS.md` и проектный документ «00_Заключение_архитектора_и_план».

## Git
- Репозиторий: GitHub, **private**, имя `nixfort`.
- Ветка `main`. Один коммит на задачу (или несколько, все с префиксом `T-00X:`).
- Никогда не коммить `.env`, `secrets/`, ключи, PCAP со стенда.
- Перед рискованной задачей: убедись, что всё закоммичено.

## Синхронизация со стендом
На `nx-controller`: `cd ~/nixfort && git pull && docker compose up -d --build`. Интеграционные тесты: `make itest`.

## Доступ Cursor к стенду (настроить один раз после T-000)
1. **Windows → ВМ.** В PowerShell: `ssh-keygen -t ed25519` (Enter на все вопросы). Содержимое `C:\Users\fraktor\.ssh\id_ed25519.pub` добавить на каждой ВМ в `/home/labadmin/.ssh/authorized_keys`.
2. Файл `C:\Users\fraktor\.ssh\config`:
```
Host nx-controller
  HostName 127.0.0.1
  Port 2210
  User labadmin
Host nx-gateway
  HostName 127.0.0.1
  Port 2220
  User labadmin
Host nx-server
  HostName 127.0.0.1
  Port 2230
  User labadmin
Host nx-client
  HostName 127.0.0.1
  Port 2240
  User labadmin
```
3. **nx-controller → узлы** (для scp/ssh внутри стенда): на nx-controller `ssh-keygen -t ed25519`, затем `ssh-copy-id labadmin@10.77.0.20`, `...30`, `...40` (пароль вводится один раз).
4. **sudo без пароля — только на лабораторных ВМ:** на каждой ВМ `echo 'labadmin ALL=(ALL) NOPASSWD:ALL' | sudo tee /etc/sudoers.d/labadmin && sudo chmod 440 /etc/sudoers.d/labadmin`.
5. В Cursor разрешить агенту выполнять команды терминала. Никогда не давать такой доступ к реальным серверам.
6. Проверка: в терминале Cursor `ssh nx-server hostname` → `nx-server`.
