# Журнал архитектурных решений (ADR)

Формат: ID · решение · почему · последствия. Новое решение добавляется вниз; старое не удаляется, а помечается «заменено ADR-xxx».

| ID | Решение | Почему | Последствия |
|---|---|---|---|
| ADR-001 | Название продукта **NIXFORT**, пространство имён в коде `nixfort` | ТЗ содержало LSSA/NIXFORT/NixFort вперемешку | Таблица `inet nixfort`, пользователь `nixfort`, файлы `*nixfort*` |
| ADR-002 | Модульный монолит Django + Celery (2 очереди) + узловой агент | Минимальная сложность для 1 разработчика, единая БД и транзакции | Нет микросервисов |
| ADR-003 | Срок 1 месяц → объём урезан (см. PROJECT_CONTEXT «НЕ входит»); 21 проверка вместо 28; 20 AT вместо 28 | Сроки руководителя проекта | Убранное → «Перспективы развития» в ВКР |
| ADR-004 | Стенд: 4 ВМ, 3 сети (mgmt/users/servers), шлюз маршрутизирует users↔servers | В ТЗ клиент и сервер были в одной подсети → трафик не шёл через шлюз, тесты firewall были бы недостоверны | `LAB_SETUP.md` |
| ADR-005 | Агент: SSH forced command + `restrict` + sudo только на лаунчер без аргументов; Python stdlib only | Нет открытых портов и демона; переносимость на Astra без зависимостей | `NODE_AGENT_PROTOCOL.md` §1 |
| ADR-006 | Конфигурации рендерит **агент** из своих шаблонов; контроллер передаёт только типизированные параметры | Исключает передачу текста конфигов/команд через сеть | Шаблоны в `agent/templates/` |
| ADR-007 | Таймер автоотката ставится **на узле** (`systemd-run`) до применения, отменяется контроллером после постпроверки | Если связь потеряна, откат с контроллера не дойдёт | Действия `mutation.*` |
| ADR-008 | Добавлены действия `net.tcp_probe.v1`, `net.send_ids_test.v1` | В ТЗ не было способа проверять соединения и генерировать тестовое событие IDS | Узел роли test_client тоже с агентом |
| ADR-009 | Nmap только `-sT -Pn -n` | SYN-scan требует root, worker не root | Профили сканирования фиксированы |
| ADR-010 | SSH: собственный `/etc/ssh/sshd_config.d/00-nixfort.conf`, проверка только через `sshd -T` | В OpenSSH «первое значение побеждает»; cloud-init кладёт `50-cloud-init.conf` | Наш файл должен сортироваться первым |
| ADR-011 | nftables: только таблица `inet nixfort`, атомарная замена `table/delete table/table` в одном файле; DENY обеспечивается `policy drop`, DENY-flow — для проверки | Не трогаем чужие правила; работает на nft старых версий (Astra 1.8) | Конфликт с ufw/firewalld → мутация запрещена |
| ADR-012 | Порядок мутаций в плане: install → fail2ban → ssh → suricata → nft | От низкого риска к высокому; механизм отлаживается на безопасном | Генератор плана |
| ADR-013 | Разрешена установка пакетов только из allowlist {fail2ban, suricata, nftables} через apt | Тема ВКР — «построение системы защиты», т.е. и установка средств; без произвольных пакетов | Необратимо, помечается в плане |
| ADR-014 | Разработка: код на Windows в Cursor, unit-тесты на SQLite локально; интеграция — на nx-controller через `git pull` + Docker Compose | 16 ГБ RAM: Docker Desktop + 4 ВМ не помещаются; Celery не работает на Windows (в unit-тестах eager) | Интеграционные тесты помечены `integration` |
| ADR-015 | Paramiko (RejectPolicy), WeasyPrint (PDF, кириллица), htmx (прогресс заданий), django-axes (лимит входа), defusedxml (Nmap XML), GitHub Actions (CI) | Зрелые, простые библиотеки | WeasyPrint импортируется лениво (на Windows может не установиться) |
| ADR-016 | ОС узлов: Ubuntu 24.04 — основная; Astra Linux SE 1.8 — проверка совместимости агента в конце, если позволит время, через `osprofile` | Тема ориентирована на отечественные ОС, но срок 1 месяц | На защите заявляем только то, что проверено |
| ADR-017 | Каждая проверка содержит `source_ref` (CIS / Рекомендации ФСТЭК по безопасной настройке Linux) | Нормативная обоснованность каталога для комиссии | Поле в каталоге |
| ADR-018 | Код пишет архитектор (Claude) в облачной среде и тестирует там; Cursor — инженер стенда (развёртывание, проверки на реальных ВМ, мелкие правки по указанию) | Сжатые сроки и требование единой выдержанной архитектуры; у архитектора нет доступа к VirtualBox, у Cursor есть | Карточки `S-xxx` для Cursor; `T-xxx` реализует архитектор |
| ADR-019 | Источник потока политики — IP или подсеть (`src_cidr`), а не узел; узел-проба обязан иметь **рабочий** (не mgmt) адрес внутри источника | Проба с mgmt-адреса не проходит через шлюз и не доказывает работу правила | `Flow.clean()` |
| ADR-020 | Образ контроллера на базе `ubuntu:24.04` (а не python-slim) | Та же ОС, что у узлов; apt из archive.ubuntu.com; Python 3.12 из дистрибутива | `deploy/Dockerfile` |
| ADR-021 | Контейнеры: `read_only`, `cap_drop: ALL`, `no-new-privileges`, пользователь uid 10001; ключ контроллера — Docker secret только в воркерах | Минимальные привилегии (SECURITY §4 п.10) | `make keys` выставляет владельца 10001 |
| ADR-022 | `Project.controller_ip` — адрес контроллера в mgmt-сети, используется как источник управления в правилах nftables и в ignoreip Fail2ban | Без него нельзя гарантировать сохранение управляющего доступа | Поле проекта |
