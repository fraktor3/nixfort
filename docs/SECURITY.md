# Безопасность NIXFORT: модель угроз и обязательные правила

NIXFORT умеет менять firewall и SSH на серверах, поэтому сам по себе — привлекательная цель. Ошибка в нём опаснее исходной ошибки конфигурации. Безопасность приложения — часть архитектуры и отдельный раздел ВКР.

## 1. Защищаемые активы
1. Приватный SSH-ключ контроллера (даёт вызов агента на всех узлах).
2. Учётные записи и сессии NIXFORT (особенно ADMIN — подтверждает изменения).
3. Целостность конфигураций узлов (sshd, nftables, fail2ban, suricata) и доступность управления.
4. Политика соединений, результаты аудитов, журнал действий, отчёты, PCAP-файлы.

## 2. Нарушители
- **Н1. Внешний/внутренний пользователь сети** без учётной записи NIXFORT (видит веб-интерфейс по сети).
- **Н2. Пользователь NIXFORT с ограниченной ролью** (VIEWER/OPERATOR), пытающийся превысить права.
- **Н3. Скомпрометированный управляемый узел** (root на узле): может подменять ответы агента.
- **Н4. Злонамеренный входной файл** (PCAP) или данные (имена, CSV-поля).
- Вне модели: компрометация root на контроллере, физический доступ, атаки на гипервизор.

## 3. Угрозы и меры
| # | Угроза | Нарушитель | Мера в NIXFORT | Проверка (тест/AT) |
|---|---|---|---|---|
| T1 | Выполнение произвольных команд через веб (command injection) | Н1, Н2 | Нет shell; только фиксированные action_id; двойная валидация параметров (контроллер + агент); конфиги рендерит агент | AT-INJ, unit-тесты инъекций |
| T2 | Агент как универсальный root-shell | Н2, Н3 | allowlist в коде агента; `restrict` + forced command; sudo только на лаунчер без аргументов; `python3 -I` | contract-тесты агента |
| T3 | Подмена узла (MITM SSH) | сеть | `RejectPolicy`, отпечаток подтверждает ADMIN; несовпадение → блокировка; подписи SSH на SHA-1 (`ssh-rsa`, `ssh-dss`) отключены, ключи RSA работают через `rsa-sha2-256/512` | AT-HOSTKEY, `execution/tests/test_ssh_algorithms.py` |
| T4 | Превышение прав, доступ к чужому проекту (IDOR) | Н2 | RBAC на сервере в каждом view и повторно в worker; чужой объект → 404 | AT-RBAC, AT-IDOR |
| T5 | Подбор пароля, кража сессии, CSRF | Н1 | django-axes по паре «логин + настоящий адрес клиента» (X-Real-IP от nginx), ограничение частоты входа в nginx (20 попыток в минуту с адреса), PBKDF2, Secure/HttpOnly/SameSite cookies, CSRF, HSTS, тайм-аут сессии 30 мин, выход только POST, страницы с данными не кэшируются браузером (`no-store`) | тесты auth, `core/tests/test_security.py` |
| T6 | Потеря управления после изменения firewall/SSH | ошибка | валидация кандидата; таймер автоотката **на узле**; проверка новым SSH-соединением; management-allow обязателен | AT-FW-RB, AT-SSH-RB |
| T7 | Уничтожение чужих правил firewall | ошибка | только таблица `inet nixfort`; запрет `flush ruleset`; детект конфликтов | AT-FW-CONFLICT |
| T8 | Ложный «успех» (оператор думает, что защищён) | ошибка | 5 статусов, PASS только с доказательством, SUCCEEDED только после постпроверки | AT-UNKNOWN |
| T9 | Повторное/параллельное выполнение изменения | ошибка, Н2 | очередь mutation (concurrency 1), lock узла, без авто-retry мутаций, неизменяемый утверждённый план (hash) | unit-тесты оркестратора |
| T10 | Вредоносный/огромный PCAP | Н4 | ≤100 MiB, magic-байты, имя = sha256, tshark без root, таймаут, лимит памяти, профили без пользовательских фильтров | AT-PCAP-* |
| T11 | Сканирование чужих сетей через NIXFORT | Н2 | цели Nmap только из узлов/CIDR проекта, проверка до запуска, `-sT` с лимитом скорости | AT-NMAP-SCOPE |
| T12 | Утечка секретов в логи/отчёты | ошибка | redaction-фильтр логов; ключ только в worker; отчёты строятся из нормализованных данных | тест redaction |
| T13 | Подделка истории действий | Н2 | AuditEvent только insert (запрет update/delete в модели и в admin) | AT-AUDIT |
| T14 | Подмена ответов агентом на скомпрометированном узле | Н3 | **Не устраняется полностью** (остаточный риск): NIXFORT доверяет root узла. Смягчение — независимые TCP-пробы с другого узла | описано в ВКР |
| T15 | Уязвимые зависимости и секреты в репозитории | supply chain | закреплённые версии, `pip-audit` в CI; поиск секретов gitleaks в CI по всей истории (`.gitleaks.toml`) | CI |
| T16 | Уязвимости веб-интерфейса: XSS, открытое перенаправление, подмена Host, clickjacking, SSRF при построении PDF | Н1, Н2 | автоэкранирование шаблонов, SVG собирается с `html.escape`; CSP без `unsafe-inline` и `unsafe-eval`, `object-src 'none'`, `frame-ancestors 'none'`, `X-Frame-Options: DENY`; `next` при входе только внутри сайта; `ALLOWED_HOSTS`; WeasyPrint не загружает ничего (`reports.views.NoFetch`); страницы просмотра принимают только GET и HEAD | `core/tests/test_security.py` |

## 4. Обязательные правила кода (проверяются при ревью)
1. Никакого `shell=True`, `os.system`, `eval/exec`, построения команд строками. `subprocess.run(list, timeout=…)` только в `agent/nixfort_agent/runner.py` и `app/apps/*/adapters/*.py`.
2. Каждый внешний вызов: таймаут, лимит вывода, проверка кода возврата, нормализованный `error_code`.
3. Валидация всех входов на границе: формы Django / схемы action. IPv4 — через `ipaddress`, порты — int-диапазон, имена — regex `^[A-Za-z0-9._-]{1,64}$`.
4. Проверка прав — в каждом view (декоратор/миксин) **и** в задании worker перед выполнением.
5. Статусы успеха только из подтверждённых фактов. По умолчанию — `UNKNOWN`.
6. Никаких секретов в репозитории, логах, `JobLog`, `Evidence`, отчётах. `.env`, `secrets/` — в `.gitignore`.
7. Журнал действий: вход/выход, неудачный вход, изменения проектов/узлов/политики, подтверждение ключа, запуск заданий, утверждение и выполнение планов, откаты, экспорт отчётов, изменение ролей.
8. Шаблоны Django — автоэкранирование не отключать (`|safe`, `mark_safe` запрещены для пользовательских данных).
9. Загрузки файлов: имя на диске не из ввода пользователя; каталог вне `static`/`media` с публичной раздачей.
10. Web и worker-контейнеры — не root (`USER nixfort`), read-only root FS где возможно; у всех контейнеров `no-new-privileges`.
11. Страница просмотра принимает только GET и HEAD (`@require_safe`), действие — только POST (`@require_POST`). Новая страница без одного из этих декораторов не проходит тест `test_viewer_cannot_write_anywhere`.

## 5. Остаточные риски (честно указываются в ВКР)
- Компрометация root контроллера = компрометация всех узлов (единый ключ). Смягчение: отдельная mgmt-сеть, доступ к контроллеру только с mgmt.
- Агент работает от root — ошибка в агенте критична. Смягчение: минимальный код, только stdlib, contract-тесты, ревью.
- Пробы с тестового клиента доказывают поведение только для протестированных пар «источник–назначение–порт».
- Suricata видит только трафик своего интерфейса; отсутствие событий ≠ отсутствие атак.
- Базовые образы (`ubuntu:24.04`, `postgres:16`, `redis:7`, `nginx:1.27`) закреплены по тегу, а не по дайджесту: пересборка получает исправления безопасности, но образ может отличаться от проверенного. Версии пакетов apt не закреплены по той же причине.
- Пароль Redis передаётся в командной строке `redis-server` и виден в `docker inspect` на контроллере (доступно только root контроллера, см. первый пункт).
- Образ по умолчанию содержит зависимости для тестов (`INSTALL_DEV=1`), чтобы `make itest` работал на стенде.
- Paramiko CVE-2026-44405 (SHA-1 в `rsakey.py`): исправленной версии нет; уязвимый алгоритм отключён в приложении (T3).

## 6. Аудит безопасности приложения (T-029, 2026-10-29)
Методика: OWASP WSTG и CIS Docker Benchmark через набор навыков Anthropic-Cybersecurity-Skills (веб-тестирование, контроль доступа, XSS, CSRF, Host, SSTI, SQLi, SSRF, open redirect, clickjacking, заголовки, SAST, секреты, SBOM, Docker, TLS).

| Проверка | Инструмент | Результат |
|---|---|---|
| Статический анализ Python | bandit, правила semgrep (python, django) | ложные срабатывания: фиксированные аргументы `subprocess`, фиксированная команда Paramiko, `csrf_token` подключается через `_form.html` |
| Уязвимые зависимости | pip-audit | paramiko CVE-2026-44405 без исправленной версии: SHA-1 отключён в `SSHTransport` |
| Секреты в коде и во всей истории git | gitleaks 8.24 | найдены только пароли тестовых пользователей в тестах (исключение в `.gitleaks.toml`) |
| Dockerfile | hadolint | только DL3008 (версии apt не закреплены, см. остаточные риски) |
| Docker Compose | ручная проверка по CIS 5.x | app-контейнеры: не root, read-only FS, `cap_drop: ALL`, `no-new-privileges`; добавлено `no-new-privileges` для postgres, redis, nginx; наружу открыты только 80 и 443 |
| nginx и TLS | `nginx -t`, запросы curl | TLS 1.2 только с ECDHE + AEAD, без session tickets; ограничение частоты входа; адрес `web` определяется заново после пересоздания контейнера (больше не нужен `restart nginx`) |
| Доступ без входа и превышение роли | тест по всем адресам приложения | каждая страница без входа ведёт на вход; наблюдатель получает 403/404/405 на любой POST и ничего не меняет |
| CSRF, open redirect, Host, XSS, clickjacking, заголовки, cookie, SSRF в PDF | `core/tests/test_security.py` | все проверки проходят |
| SQL-инъекции, SSTI | поиск по коду | нет `raw()`, `extra()`, сырого SQL с вводом пользователя; шаблоны из строк не строятся |

Исправлено: SHA-1 в SSH, страницы просмотра принимали POST, страницы с данными могли кэшироваться браузером, блокировка входа считала адрес контейнера nginx вместо адреса клиента, PDF-движок мог загружать внешние адреса, nginx без ограничения частоты входа и с устаревшими наборами шифров, `no-new-privileges` не у всех контейнеров, поиск секретов не входил в CI.
