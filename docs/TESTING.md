## 1. Уровни тестов
| Уровень | Где | Что | Команда |
|---|---|---|---|
| Unit | Windows (SQLite) и CI | валидаторы, RBAC, переходы состояний, оценка 21 проверки на фикстурах, генератор плана, рендер шаблонов агента, парсеры Nmap/TShark/sshd -T | `pytest -m "not integration"` |

## 3. Эксперимент для ВКР
**Гипотеза.** Единый процесс NIXFORT (аудит → план → применение с автооткатом → постпроверка → отчёт) сокращает время и число ручных действий при усилении защиты Linux-сегмента по сравнению с ручным выполнением тех же мер теми же инструментами, не ухудшая сохранность разрешённых соединений и полноту обнаружения дефектов.

**Набор дефектов** (`lab/inject_defects.sh`, применяется к снапшоту «чистый стенд»): 8 дефектов — PermitRootLogin yes, PasswordAuthentication yes, MaxAuthTries 10, X11Forwarding yes, jail sshd выключен, лишний сервис :8080, на шлюзе нет фильтрации forward, Suricata смотрит не на тот интерфейс.

**Процедуры.**
- A (вручную): по инструкции `lab/manual_procedure.md` — ssh на узлы, проверки командами, правка конфигов, nft-правила, проверка `nc`, отчёт в шаблон.
- B (NIXFORT): тот же объём через веб-интерфейс.
Каждая процедура — 3 повтора с восстановлением снапшотов.

**Метрики:** время до готового отчёта (мин); число ручных команд/действий; доля найденных дефектов из 8; число ложных PASS; доля разрешённых соединений, сохранившихся после изменений; время восстановления после ошибочного изменения (AT-13); полнота отчёта (наличие 7 обязательных элементов).

**Ограничения (указать в ВКР):** один исполнитель (автор), эффект обучения, искусственный набор дефектов, лабораторный стенд. Выводы — только в пределах стенда.
